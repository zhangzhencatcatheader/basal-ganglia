📌 项目定位

basal-ganglia 是垂直行业台账/工单类项目通用底座，
统一沉淀所有 ToB、监管类、履约类、巡检类系统的公共不变量。

• 上层业务千变万化（养老 / 煤矿 / 物业 / 医疗台账）

• 基底节永久不变：权限、工单、流转、通知、存证、外部网关

设计理念：
业务在上，底座在下；业务常新，底座恒稳。
🚀 技术栈

• 核心框架：Vert.x（事件驱动、异步非阻塞、高吞吐）

• ORM 框架：Jimmer（强类型、动态 SQL、关联极致、DTO 自动生成）

• 数据库：PostgreSQL（JSONB、事务严谨、数值精准、可分区）

• 通信机制：Vert.x EventBus 标准化事件驱动

• 设计模型：CQRS 思想、事件驱动、业务与底座彻底解耦

• 运行模型：EventLoop 处理调度 + Worker 池隔离阻塞 DB 操作
🧱 底座包含服务（完全可移植、零业务耦合）

1. service-iam 身份权限中枢

• 统一账号、角色、资源、数据权限

• RBAC 权限体系

• 第三方登录绑定

• 通用代办、委托、可撤回授权模型（台账系统核心通用能力）

• 用户扩展字段 JSONB 动态适配多行业

2. service-workflow 通用工单履约引擎（核心资产）

完全通用的行业无关工单引擎：

• 工单创建、派发、接单、拒单、流转闭环

• 可配置超时转派、自动兜底、自动办结

• GPS 签到校验、距离偏移预警

• 服务凭证、拍照留痕、时间戳存证

• 统一 bizType 区分不同业务场景

• 扩展字段隔离业务差异，底座代码永不改动

3. service-notify 消息调度中心

• 小程序模板消息

• 站内通知、事件推送

• 短信通知

• 消息重试、失败回执、日志留存

• 统一事件订阅，完全解耦业务触发方

4. service-file 文件存证服务

• OSS 统一上传、鉴权

• 图片水印、时间戳、位置留痕

• 监管系统必备存证链路

• 文件元数据入库、可溯源、可审计

5. service-external-gateway 第三方适配网关

所有外部调用统一收口：

• 外部 HTTP 异步调用、熔断、重试

• 多平台适配器可插拔扩展

• 上报日志、回调日志全留存

• 隔离外部不稳定依赖，保护内部核心链路
📐 核心架构设计规范

1. 分层原则

• 基底节层：不变、通用、稳定、可复用

• 业务应用层：多变、行业定制、独立迭代

2. 解耦铁律

• 底座不写任何业务判断、行业规则、业务计算公式

• 所有业务差异通过 bizType + JSONB ext + 业务扩展表实现

• 服务通信只依赖标准化 EventBus 事件，不直接接口硬调用

3. Vert.x 运行铁律

• EventLoop 禁止任何阻塞操作

• Jimmer / JDBC / 复杂计算 全部托管 Worker 线程池

• 保证整个底座高吞吐、不抖动、不卡死

4. 数据库设计规范

• 多 Schema 隔离：iam / workflow / notify / file / external

• 公共字段统一：时间戳、创建人、状态

• 金额、结算全部使用 numeric 杜绝精度错误

• 动态业务属性统一 JSONB 扩展
📡 标准化事件契约（底座统一标准）

所有底座事件遵循统一结构，跨项目永久兼容：
{
  "eventId": "唯一事件ID",
  "eventType": "事件类型",
  "bizType": "业务场景标识",
  "bizId": "业务主键ID",
  "tenantId": "租户/片区ID",
  "payload": {}
}
通用事件类型

• WORKFLOW_CREATED 工单创建

• WORKFLOW_DISPATCHED 工单派发

• WORKFLOW_FINISHED 工单办结

• NOTIFY_REQUIRE 消息触发

• FILE_UPLOADED 文件存证完成

• EXTERNAL_REPORTED 外部上报完成
